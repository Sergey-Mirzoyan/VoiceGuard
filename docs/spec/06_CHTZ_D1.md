# ЧТЗ-06. D1: базовый акустический детектор (LFCC-LCNN)

Основание: общее ТЗ, разделы 7, 8, 10. Зависимости: ЧТЗ-02, ЧТЗ-03.

## 1. Цель

Построить стандартный акустический детектор синтеза, обученный на армянской речи после телефонного канала. Он служит точкой отсчёта: D2 должен показать вклад сверх D1 (ворота G1), а в продукте D1 и D2 работают вместе.

Архитектура — LFCC-LCNN, базовая система соревнования ASVspoof 2021, адаптированная к 8 и 16 кГц.

## 2. Объём работ

Входит: извлечение LFCC, модель LCNN, обучение с канальной аугментацией, инференс на сегментах по 1 с, сохранение модели, CLI, простой запасной классификатор (LFCC + логистическая регрессия) для быстрых проверок.

Не входит: самообучающиеся модели (wav2vec 2.0, XLS-R, AASIST) — кандидаты на следующую версию.

## 3. Функциональные требования

**FR-01. LFCC.** `voiceguard.d1.features.lfcc(samples, sr) -> np.ndarray[frames, 60]`: кадр 20 мс, шаг 10 мс, БПФ 256 (8 кГц) или 512 (16 кГц), 20 линейных треугольных фильтров от 0 до sr/2, логарифм, DCT, 20 коэффициентов + Δ + ΔΔ. Нормализация: среднее и дисперсия по сегменту (CMVN).

**FR-02. Модель.** `voiceguard.d1.model.LCNN` (PyTorch): 4–6 свёрточных блоков с активацией Max-Feature-Map и батч-нормализацией, пулинг по времени, полносвязный выход с одним логитом (spoof против live). Число параметров — не более 1 млн. Две конфигурации: `nb` (8 кГц) и `wb` (16 кГц).

**FR-03. Обучение.** `python -m voiceguard.d1 train --band nb`:

- данные: часть `train` (ЧТЗ-02), генератор `f5tts` и живая речь; генератор `mms` в обучение не входит;
- каждый пример — случайный сегмент 1 с, пропущенный через случайный канал из пула (`channel.random_spec`, ЧТЗ-03); пул для `nb`: `g711a`, `g711u`, все режимы `amrnb`, с потерями 0–5% и SNR ∞/30/20/10 дБ;
- валидация: 10% дикторов части `train`, фиксированный набор каналов; ранняя остановка по EER на валидации (терпение 5 эпох);
- оптимизатор Adam, lr 1e-3, batch 64, до 50 эпох, взвешенная функция потерь при дисбалансе классов;
- модель и метаданные (конфигурация, EER на валидации, хеш данных) сохраняются в `data/models/d1_{band}.pt` и `d1_{band}.json`.

**FR-04. Инференс.** `voiceguard.d1.infer.score(segment: Segment, model) -> float` — логит `s1` (больше — вероятнее синтез). `load_model(band) -> LCNN` загружает модель на CPU.

**FR-05. Запасной классификатор.** `python -m voiceguard.d1 train-lr --band nb`: средние и стандартные отклонения LFCC по сегменту (120 признаков) + логистическая регрессия. Нужен для быстрых проверок конвейера и как нижняя граница качества.

**FR-06. Оценка.** `python -m voiceguard.d1 eval --band nb --channels amrnb_12.2,g711a --split test` выводит EER и ROC AUC по каналам и генераторам (включая невиданный `mms`), результат сохраняется в `reports/d1_eval.json`.

## 4. Нефункциональные требования

- Инференс сегмента 1 с на CPU (1 ядро): не более 20 мс.
- Обучение `nb` на наборе с `--limit 2000` клипов на класс: не более 3 часов на 8 ядрах CPU без GPU. Если время превышено, допустимо уменьшить модель; изменение фиксируется в отчёте.

## 5. Критерии приёмки

- **AC-01.** Тест: `lfcc` на 1 с при 8 кГц возвращает массив формы (≈100, 60) без NaN.
- **AC-02.** Тест: прямой проход LCNN на батче (8, frames, 60) даёт (8,) логитов; число параметров ≤ 1 млн.
- **AC-03.** Тест: обучение 2 эпохи на фикстуре из 20 клипов проходит и сохраняет модель; `score` возвращает число.
- **AC-04.** На реальных данных (`--limit 2000`) `eval` на `amrnb_12.2`, генератор `f5tts`, часть `test` показывает EER ниже 20%. Если нет — отчёт с анализом причин (это допустимый результат этапа, но должен быть объяснён).
- **AC-05.** В отчёте `eval` есть строка для невиданного генератора `mms` (если он собран в ЧТЗ-02).
