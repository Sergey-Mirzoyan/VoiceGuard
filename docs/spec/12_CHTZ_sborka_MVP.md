# ЧТЗ-12. Сборка MVP, демо-сценарий, документация

Основание: общее ТЗ, раздел 12. Зависимости: ЧТЗ-10, ЧТЗ-11.

## 1. Цель

Собрать все части в образец, который поднимается одной командой, проходит сквозные тесты и воспроизводимо показывает демонстрацию для питча.

## 2. Объём работ

Входит: `docker-compose.yml`, цели Makefile, набор демо-звонков, сквозные тесты, прогон демо-сценария с измерениями, итоговый паспорт, документация.

Не входит: новая функциональность модулей (только исправления, найденные при интеграции, — с описанием в отчёте).

## 3. Функциональные требования

**FR-01. docker-compose.** Сервисы `asterisk`, `engine`, `ui`; общий том `data/models`; переменные окружения в `.env.example`; проверки здоровья (`healthcheck`) для всех сервисов; порядок запуска через `depends_on` с условием `service_healthy`.

**FR-02. Цели Makefile.**

| Цель | Действие |
|---|---|
| `demo` | Сборка образов и запуск стенда; печать адреса панели и параметров для софтфона |
| `demo-down` | Остановка и очистка |
| `demo-calls` | Серия звонков бота по `demo/calls.csv` |
| `e2e` | Сквозные тесты FR-04 |
| `passport` | Вывод паспорта |

**FR-03. Набор демо-звонков.** `demo/calls.csv` и `demo/audio/`: 10 файлов (5 живых, 5 синтетических, по 15–25 с), дикторы и тексты — только из части `test`, синтез — из обоих генераторов (если `mms` собран). Отдельно 2 «эффектных» файла для питча: живая фраза и её синтезированный клон одним голосом (если клон можно получить законно — из синтетического датасета, без клонирования реальных людей без согласия). Лицензии файлов — в `demo/README.md`.

**FR-04. Сквозные тесты** (`tests/e2e/`, запуск в Docker):

1. тестовый режим (ЧТЗ-10, FR-07): вся цепочка «бот → Asterisk → движок → предупреждение → событие на панели» работает для `spoof` и не срабатывает для `live`;
2. боевой режим: 10 демо-звонков проходят без ошибок; для каждого есть вердикт или `undecided` не позже `t_max_s`; результаты пишутся в `reports/demo/{run_id}.json`;
3. отсутствие записанного звука на диске во всех контейнерах после прогона (проверка каталогов и временных файлов).

**FR-05. Демо-сценарий.** `docs/DEMO.md` — пошаговый сценарий на 5–7 минут:

1. что показываем и почему (1 абзац);
2. запуск и проверка стенда до выступления (чек-лист);
3. живой звонок с софтфона 101 на 100 — вердикт «Норма»;
4. звонок бота с синтезированным голосом — предупреждение в трубке и на панели;
5. экран «Анализ файла» — раздел «Подробно о D2»: как метод из диссертации видит синтез;
6. экран «Паспорт» — честные цифры α, β и время до вердикта;
7. ответы на ожидаемые вопросы: WhatsApp и мессенджеры, приватность, ложные тревоги, новые модели синтеза (по концепту);
8. запасной план при сбое сети или звука (запись экрана демо, `make demo-calls` без софтфона).

**FR-06. Итоговый паспорт и отчёт MVP.** `reports/mvp/report.md`: состав и версии, итог ворот G1 (из ЧТЗ-07), результаты демо-прогона (вердикт по каждому звонку, время до вердикта), паспорт, производительность (RTF, задержки), известные ограничения, рекомендации к следующей версии.

**FR-07. Документация.** `README.md` (обзор, быстрый старт), `docs/ARCHITECTURE.md` (схема и потоки данных по общему ТЗ), `docs/OPERATIONS.md` (конфигурация, переменные, журналы, отладка), ссылки на `docs/spec/`.

## 4. Критерии приёмки

Соответствуют разделу 12 общего ТЗ:

- **AC-01.** `make demo` на чистой машине (Docker, 4 ядра, 8 ГБ ОЗУ, без GPU) поднимает стенд; панель доступна; софтфон подключается по инструкции.
- **AC-02.** `make e2e` проходит все три группы тестов FR-04.
- **AC-03.** Демо-сценарий проведён по `docs/DEMO.md` не менее двух раз подряд без сбоев; отчёт MVP содержит результаты.
- **AC-04.** RTF ≤ 0,5 и задержка вердикта в пределах ЧТЗ-09 на демо-прогоне.
- **AC-05.** Паспорт заполнен по итогам демо-прогона и прогона ЧТЗ-08; в отчёте MVP нет ни одного числа, которое не получено измерением.
