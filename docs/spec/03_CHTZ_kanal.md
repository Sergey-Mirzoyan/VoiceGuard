# ЧТЗ-03. Симулятор телефонного канала

Основание: общее ТЗ, разделы 7, 8, 10. Зависимости: ЧТЗ-01.

## 1. Цель

Воспроизвести искажения телефонного тракта, через которые проходит голос звонящего: узкополосные и широкополосные кодеки, потери пакетов, фоновый шум. Все эксперименты и обучение идут только на сигнале, прошедшем через симулятор.

## 2. Объём работ

Входит: кодеки G.711 (A-law, µ-law), AMR-NB (все 8 режимов), AMR-WB (все 9 режимов), потери кадров, аддитивный шум, строковый формат спецификации канала, пакетная обработка, потоковый режим для движка.

Не входит: эхо, АРУ телефона, акустика помещения (могут быть добавлены позже).

## 3. Функциональные требования

**FR-01. Строковый формат.** `ChannelSpec.parse(s: str) -> ChannelSpec` и `str(spec)`. Грамматика: `codec[_bitrate][+lossX][+snrY]`. Примеры: `clean`, `g711a`, `amrnb_12.2`, `amrnb_4.75+loss3`, `amrwb_12.65+snr20`. Недопустимый битрейт для кодека вызывает `ValueError` со списком допустимых.

Допустимые битрейты, кбит/с: AMR-NB — 4.75, 5.15, 5.9, 6.7, 7.4, 7.95, 10.2, 12.2; AMR-WB — 6.6, 8.85, 12.65, 14.25, 15.85, 18.25, 19.85, 23.05, 23.85.

**FR-02. Применение канала.** `voiceguard.channel.apply(clip: AudioClip, spec: ChannelSpec, seed: int) -> AudioClip`.

- Выходная частота: 8 кГц для `g711*` и `amrnb`, 16 кГц для `amrwb` и `clean` (для `clean` частота входа сохраняется).
- Порядок: ресэмплинг до частоты кодека → шум (если задан) → кодирование → потери кадров → декодирование.
- Выходной клип имеет ту же длительность, что и входной (с точностью до одного кадра 20 мс); задержка кодека компенсируется выравниванием по взаимной корреляции.
- В `meta` выходного клипа записываются `channel=str(spec)` и фактическая доля потерянных кадров.

**FR-03. Кодирование через ffmpeg.** Вызов ffmpeg через `subprocess` с передачей данных через stdin/stdout (без временных файлов на диске, где это возможно). Энкодеры: `libopencore_amrnb`, `libvo_amrwbenc`; декодеры: встроенные `amrnb`, `amrwb`. G.711 допускается реализовать на numpy без ffmpeg.

**FR-04. Потери кадров.** Потери моделируются на уровне битового потока AMR (формат хранения RFC 4867, 20 мс на кадр): выбранные кадры помечаются как потерянные (тип кадра NO_DATA или бит качества Q = 0), чтобы сработало штатное маскирование декодера. Модель потерь — независимые потери с вероятностью `loss_pct` (по умолчанию) и опционально пакетная модель Гилберта–Эллиотта (параметры в конфигурации). Если декодер ffmpeg не выполняет маскирование помеченных кадров, допускается маскирование на уровне PCM (повтор предыдущего кадра с затуханием 6 дБ на каждый следующий потерянный кадр). Выбранный способ описывается в README модуля и в отчёте о сдаче.

**FR-05. Шум.** Аддитивный шум с заданным SNR по активной речи. Источник — набор фоновых шумов (улица, офис, транспорт), указанный в конфигурации; если набор не задан, используется розовый шум. Для сигнала без шума `snr_db = None`.

**FR-06. Пакетная обработка.** `python -m voiceguard.channel run --split test --channels amrnb_12.2,g711a --workers 4` обрабатывает клипы из манифеста и кэширует результат в `data/channel/{channel}/{clip_id}.flac`. Повторный запуск использует кэш.

**FR-07. Случайный канал для аугментации.** `voiceguard.channel.random_spec(rng: np.random.Generator, pool: list[str]) -> ChannelSpec` — выбор канала из пула для обучения D1 (ЧТЗ-06).

**FR-08. Потоковый режим.** `voiceguard.channel.StreamTranscoder(spec)` с методом `push(pcm: np.ndarray) -> np.ndarray` для обработки потока кадрами по 20 мс с задержкой не более 60 мс. Используется движком (ЧТЗ-09) для имитации AMR на стенде. Реализация: долгоживущий процесс ffmpeg с потоковыми stdin/stdout либо библиотечная привязка к opencore-amr.

## 4. Нефункциональные требования

- Пакетная обработка 1 часа речи через `amrnb_12.2` занимает не более 10 минут на 4 ядрах.
- Результат детерминирован при одинаковом `seed` (потери и шум).

## 5. Критерии приёмки

- **AC-01.** Тесты разбора и печати спецификаций, включая ошибки для недопустимых битрейтов.
- **AC-02.** Тест: синус 440 Гц через `amrnb_12.2` сохраняет основную частоту (±5 Гц) и длительность (±20 мс).
- **AC-03.** Тест: `g711a` на речи даёт SNR относительно входа не ниже 30 дБ после выравнивания.
- **AC-04.** Тест: `+loss10` на клипе 10 с даёт фактическую долю потерь 7–13% при фиксированном `seed`, результат воспроизводим.
- **AC-05.** Тест: после `amrnb_*` спектр выше 4 кГц пуст (энергия выше 3.8 кГц на 40 дБ ниже общей).
- **AC-06.** `StreamTranscoder` на клипе 5 с даёт результат, совпадающий с пакетным `apply` по корреляции ≥ 0,95 после выравнивания.
- **AC-07.** Отчёт о сдаче описывает способ моделирования потерь (FR-04).
