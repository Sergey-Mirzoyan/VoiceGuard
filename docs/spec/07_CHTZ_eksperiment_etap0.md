# ЧТЗ-07. Эксперимент этапа 0 и ворота G1

Основание: общее ТЗ, разделы 9, 11; документ «Предсказательный тест синтетического голоса», раздел 2.8. Зависимости: ЧТЗ-02, 03, 05, 06.

## 1. Цель

Одной командой провести эксперимент этапа 0 и получить отчёт, по которому заказчик принимает решение на воротах G1: даёт ли D2 значимое различение живой и синтезированной армянской речи после телефонного канала и вклад сверх D1.

## 2. Объём работ

Входит: построение эталонов, прогон D1 и D2 по тестовой части во всех каналах, метрики, статистические тесты, графики, отчёт, автоматическая проверка критериев G1.

Не входит: SPRT и потоковый режим (ЧТЗ-08, 09).

## 3. Функциональные требования

**FR-01. Команда.** `make stage0` (или `python -m voiceguard.experiments.stage0 --config configs/default.yaml`) последовательно:

1. проверяет наличие манифеста и моделей D1 (при отсутствии — понятная ошибка с командой для их создания);
2. строит эталоны D2 (ЧТЗ-05, FR-06) для всех каналов `channels.stage0`, вариантов A (кадры `all`, `voiced`, `unvoiced`) и B;
3. считает на части `test` для каждого сегмента: `s1` (D1), `D2Result` для всех вариантов, значения δ и ρ по всем проверкам;
4. сохраняет сырые результаты в `reports/stage0/{run_id}/scores.parquet` (одна строка на сегмент × канал × вариант);
5. считает метрики и формирует отчёт.

Длительность сегмента для варианта A — 1 с и 5 с (5 с — склейка пяти последовательных сегментов одного клипа); для варианта B — 5 с.

**FR-02. Метрики.** Для каждого сочетания канал × вариант × класс кадров × длительность:

- распределения δ_j и ρ для live и spoof: среднее, стандартное отклонение, квантили;
- критерий Манна–Уитни live против spoof по каждой проверке и по s₂ (p-значение, поправка Холма по числу проверок);
- ROC AUC и EER статистики s₂; 95% доверительный интервал AUC бутстрепом по дикторам (1000 повторов);
- то же для `s1` (D1);
- слияние D1 + D2: логистическая регрессия на `(s1, s2)`, обученная на части `calib` с синтезом (калибровочный набор с синтезом формируется из `calib` без пересечения дикторов с `test`); AUC на `test`;
- тест ДеЛонга для сравнения AUC(D1 + D2) и AUC(D1) на одних и тех же сегментах;
- корреляция ошибок D1 и D2 при пороге EER (ортогональность);
- отдельная строка для невиданного генератора `mms`;
- σ_spk из эталонов (ЧТЗ-05, FR-06) и фактическая чувствительность Δ_min = (z_{α/(2m)} + z_β)·σ0 при β = 0,2.

**FR-03. Графики** (`reports/stage0/{run_id}/fig/`): гистограммы δ для live и spoof по ключевым проверкам (чистый звук против `amrnb_12.2`), ROC-кривые D1, D2, D1 + D2 по каналам, зависимость AUC D2 от канала (столбцы с доверительными интервалами), зависимость AUC от длительности сегмента.

**FR-04. Отчёт.** `reports/stage0/{run_id}/report.md` на русском языке:

1. условия эксперимента: версия кода, конфигурация, объёмы данных по частям, каналы;
2. основные результаты: таблица AUC и EER (D1, D2-A, D2-B, D1 + D2) по каналам;
3. ответы на гипотезы H1–H4 (формулировки — в документе концепта, раздел 9.1) с числами;
4. проверка ворот G1 по трём критериям (FR-05) — «выполнен / не выполнен» с числами;
5. ограничения и угрозы достоверности (объём данных, один генератор в обучении, особенности разбиения);
6. рекомендация: какой вариант D2 (A, B, класс кадров) брать в фазу B либо отключить D2 в потоковом режиме.

Дополнительно — `summary.json` со всеми числами отчёта.

**FR-05. Автоматическая проверка G1.** Критерии (параметры в конфигурации `gate_g1`):

- в варианте A или B распределения live и spoof различаются после `amrnb_12.2` (Манн–Уитни с поправкой Холма, p < 0,01) хотя бы по одной проверке;
- AUC одного D2 на сегментах 5 с после `amrnb_12.2` не ниже 0,75 (нижняя граница 95% интервала указывается рядом);
- AUC(D1 + D2) > AUC(D1) по тесту ДеЛонга, p < 0,05.

Итог G1 — «пройдено», только если выполнены все три. Решение о переходе к фазе B принимает заказчик; отчёт даёт рекомендацию.

**FR-06. Быстрый режим.** `make stage0-quick` — тот же прогон на `--limit 200` клипов и двух каналах (`clean`, `amrnb_12.2`) для отладки, не дольше 30 минут.

## 4. Нефункциональные требования

- Полный прогон на данных `--limit 2000` — не более 12 часов на 8 ядрах без GPU. Прогон можно возобновить после прерывания: готовые части результатов не пересчитываются.
- Все результаты воспроизводимы по `run_id` (конфигурация и хеш кода сохраняются в каталог прогона).

## 5. Критерии приёмки

- **AC-01.** `make stage0-quick` завершается и создаёт `report.md`, `summary.json`, графики.
- **AC-02.** Тест: реализация ДеЛонга совпадает с эталонным примером (два классификатора на синтетических данных с известной разницей) с точностью 1e-3 по p-значению относительно эталонной реализации (например, из пакета `pROC` или опубликованного Python-порта).
- **AC-03.** Тест: при подаче D2 одинаковых распределений для live и spoof (перемешанные метки) критерии G1 не выполняются, AUC ≈ 0,5 ± 0,05.
- **AC-04.** Полный прогон `make stage0` выполнен на данных `--limit 2000`; отчёт содержит все разделы FR-04 и итог G1 с числами.
- **AC-05.** Отчёт прямо указывает, какие результаты получены на невиданном генераторе.
