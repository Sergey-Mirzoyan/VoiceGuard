# VoiceGuard AM — Техническое задание на тестовый образец (MVP)

Версия 1.0 · 27.09.2026 · Заказчик: С. А. Мирзоян

Документ задаёт общие требования. Работы выполняются по частным ТЗ (ЧТЗ-01 … ЧТЗ-12), каждое ЧТЗ ссылается на этот документ. При противоречии приоритет у общего ТЗ; противоречие фиксируется и сообщается заказчику.

## 1. Назначение

Тестовый образец обнаруживает синтезированную (дипфейк) армянскую речь в телефонном канале и выдаёт абоненту предупреждение во время звонка.

Образец решает две задачи:

1. **Исследовательская (этап 0).** Проверить гипотезу: предсказательный тест из диссертации (тест на следующий бит, метрика δ, порог ε) отличает синтез от живой речи после телефонного кодека. Сравнить его с базовым акустическим детектором.
2. **Демонстрационная (этап 1).** Показать на стенде: идёт звонок, через несколько секунд речи звонящего абонент слышит предупреждение, а на панели видны показатели детекторов.

## 2. Термины

| Термин | Значение |
|---|---|
| bona fide / live | Живая речь человека |
| spoof / synthetic | Синтезированная или преобразованная речь |
| D1 | Акустический детектор синтеза (нейросеть на LFCC) |
| D2 | Предсказательный детектор (метод диссертации) |
| Вариант A | D2 на LPC-остатке сигнала |
| Вариант B | D2 на последовательности периодов основного тона |
| Канал 𝒞 | Модель телефонного тракта: кодек, потери пакетов, шум |
| Эталон | Статистики μ₀, σ₀ живой речи для каждого канала и проверки |
| SPRT | Последовательный критерий отношения правдоподобия Вальда |
| Сегмент | 1 с речи после VAD — единица анализа |
| Паспорт детектора | JSON с измеренными α, β, временем до вердикта и условиями |

## 5. Технологический стек

- Python 3.11, управление зависимостями — `uv` (допускается `poetry`), единый `pyproject.toml`.
- Численные библиотеки: `numpy`, `scipy`, `pandas`, `pyarrow`, `scikit-learn`, `librosa`, `soundfile`.
- Нейросети: `torch` (CPU; GPU необязателен и не требуется для приёмки).
- Речь: `webrtcvad` (или `silero-vad`), `praat-parselmouth` (основной тон).
- Данные: `datasets` / `huggingface_hub`.
- Кодеки: системный `ffmpeg` с энкодерами `libopencore_amrnb` и `libvo_amrwbenc`.
- Сервис: `fastapi`, `uvicorn`, `pydantic` v2.
- Панель: `streamlit`, `plotly`.
- Телефония: Asterisk 20 (PJSIP, ARI), HTTP-клиент `httpx`, `websockets`.
- Качество: `pytest`, `ruff`, `mypy` (строгость — по умолчанию), `pre-commit`.
- Контейнеры: Docker, docker-compose.

Новые зависимости добавляются только при необходимости и с обоснованием в описании изменений.

## 7. Общие типы данных (`src/voiceguard/types.py`)

Все модули обмениваются только этими типами. Изменение типов — только через заказчика.

```python
from dataclasses import dataclass, field
from enum import Enum
import numpy as np

class Label(str, Enum):
    LIVE = "live"
    SPOOF = "spoof"

@dataclass(frozen=True)
class AudioClip:
    samples: np.ndarray          # float32, моно, диапазон [-1, 1]
    sr: int                      # 8000 или 16000
    clip_id: str
    meta: dict = field(default_factory=dict)

@dataclass(frozen=True)
class ChannelSpec:
    codec: str                   # "clean" | "g711a" | "g711u" | "amrnb" | "amrwb"
    bitrate_kbps: float | None   # для AMR: 4.75 … 12.2 (NB), 6.6 … 23.85 (WB)
    loss_pct: float = 0.0        # доля потерянных кадров, %
    snr_db: float | None = None  # None — без шума
    # строковая форма: "amrnb_12.2+loss3+snr20"; см. ЧТЗ-03

@dataclass(frozen=True)
class Segment:
    samples: np.ndarray          # 1 с речи после VAD
    sr: int
    voiced_mask: np.ndarray      # bool по кадрам 20 мс
    clip_id: str
    index: int                   # номер сегмента в клипе

@dataclass(frozen=True)
class D2Result:
    delta: dict[str, float]      # по check_id, напр. "A_bit_w16_fwd"
    z: dict[str, float]          # стандартизованные отклонения от эталона
    s2: float                    # max |z|
    chi2_p: dict[str, float]     # p-значения хи-квадрат
    n_symbols: int
    variant: str                 # "A" | "B"

@dataclass(frozen=True)
class WindowScore:
    t: float                     # время конца сегмента, с
    s1: float | None             # логит D1
    s2: float | None             # статистика D2
    llr: float                   # слитое лог-отношение правдоподобия
    Lambda: float                # накопленная статистика SPRT
    verdict: str                 # "pending" | "suspicious" | "normal" | "undecided"
```

Идентификатор проверки D2: `{variant}_{mode}_w{w}_{dir}`, где variant ∈ {A, B}, mode ∈ {bit, block}, w ∈ {8, 16, 32}, dir ∈ {fwd, bwd}. Пример: `A_block_w32_bwd`.

## 10. Общие требования ко всем ЧТЗ

1. **Тесты.** Каждая публичная функция покрыта модульными тестами в `tests/`. `make test` проходит без сети и без полных датасетов (используются синтетические сигналы и фикстуры до 5 с звука).
2. **Детерминизм.** Все случайные процессы используют `seed` из конфигурации. Повторный прогон на тех же данных даёт тот же результат.
3. **Качество кода.** `make lint` (ruff + mypy) без ошибок. Типы в сигнатурах обязательны. Докстринги на английском, комментарии и отчёты — на русском или английском.
4. **Границы изменений.** Агент меняет только файлы своего модуля, `tests/` своего модуля, `configs/default.yaml` и модели в `config.py` (только свои разделы: новые параметры, которые вводит его ЧТЗ, добавляются туда со значениями по умолчанию) и `pyproject.toml` (только зависимости). Публичные интерфейсы других модулей и `types.py` не меняются.
5. **Конфиденциальность.** Потоковый режим (ЧТЗ-09, 10) не записывает звук на диск. Отладочная запись допустима только с явным флагом `debug.save_audio: true` (по умолчанию `false`).
6. **Данные.** Датасеты не добавляются в git. Лицензия каждого датасета фиксируется в `data/README.md`.
7. **Сдача этапа.** Агент прикладывает: список изменённых файлов, вывод `make test` и `make lint`, выполнение каждого критерия приёмки ЧТЗ, известные ограничения и открытые вопросы.
8. **Неясности.** Если требование ЧТЗ неоднозначно или невыполнимо, агент не додумывает молча. Он выбирает самый консервативный вариант, реализует его и явно описывает выбор в отчёте о сдаче.

## 11. Ключевые формулы (справочно; детали — в ЧТЗ)

LPC-остаток:

```
e[n] = x[n] − Σ_{k=1..p} a_k · x[n−k]
```

Бинаризация: `b[n] = 1{ e[n] > median_frame(e) }`.

Уровень предсказуемости: `δ = p̂ − 0.5`, где p̂ — точность предсказателя на тестовой части.

Статистика относительно эталона живой речи:

```
Z_j = (δ_j − μ0_j(𝒞)) / σ0_j(𝒞),    s2 = max_j |Z_j|,    m = 12
подозрение по D2  ⇔  s2 > z_{α/(2m)}         (α = 0.01 → 3.34)
```

SPRT:

```
Λ_T = Σ_t llr_t
Λ_T ≥ ln((1−β)/α) → "suspicious";   Λ_T ≤ ln(β/(1−α)) → "normal";   T ≥ T_max → "undecided"
```

## 12. Приёмка MVP

MVP принят, если выполнены все пункты:

1. Все ЧТЗ сданы с выполненными критериями приёмки.
2. Отчёт этапа 0 сформирован и содержит проверку ворот G1 (результат может быть и отрицательным: важна корректность измерения).
3. На стенде `make demo` поднимает систему одной командой на машине с Docker, 4 ядрами CPU и 8 ГБ ОЗУ без GPU.
4. Демо-сценарий (ЧТЗ-12) проходит: для каждого из 10 тестовых звонков (5 живых, 5 синтетических, дикторы не из обучения) система выдаёт вердикт или «нет решения» не позже T_max, панель показывает ход анализа, при вердикте «подозрение» абонент слышит предупреждение.
5. Потоковый движок обрабатывает звук быстрее реального времени (RTF ≤ 0.5) в конфигурации, выбранной по итогам ЧТЗ-09.
6. Измеренные на тестовых звонках α, β и среднее время до вердикта записаны в паспорт детектора.

Точность детекции не является условием приёмки MVP: MVP должен честно её измерить.
