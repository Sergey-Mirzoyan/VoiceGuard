# ЧТЗ-08. Слияние детекторов, последовательное решение, паспорт

Основание: общее ТЗ, разделы 7, 8, 11; концепт, разделы 5.5, 5.6, 6.3. Зависимости: ЧТЗ-07 (и решение заказчика по воротам G1).

## 1. Цель

Превратить посекундные оценки D1 и D2 в решение по звонку с заданной долей ложных тревог: калибровка оценок в лог-отношение правдоподобия, накопление по критерию Вальда (SPRT), эмпирическая проверка α и β, паспорт детектора.

## 2. Объём работ

Входит: калибратор, SPRT, симуляция звонков на офлайн-данных, эмпирические α/β с доверительными границами, подбор порогов, паспорт, CLI.

Не входит: потоковая обработка звука (ЧТЗ-09).

## 3. Функциональные требования

**FR-01. Состав признаков.** Флаги конфигурации `fusion.use_d1`, `fusion.use_d2` (по итогам G1). Вариант и класс кадров D2 задаются по рекомендации отчёта ЧТЗ-07 (`fusion.d2_variant`, `fusion.d2_frames`).

**FR-02. Калибратор.** `voiceguard.fusion.calibration.fit(scores: pd.DataFrame) -> Calibrator` — логистическая регрессия на сегментных признаках `(s1, s2)` (или одном из них), обученная на части `calib` после канала из `fusion.calib_channels`. Для сегмента:

```
llr_t = logit(P(spoof | s)) − ln(π1 / (1 − π1))
```

где π1 — доля spoof в обучающем наборе калибратора (вычитание априорных шансов превращает апостериорный логит в отношение правдоподобия). `Calibrator.llr(s1, s2) -> float`. Сохранение в `data/models/calibrator.json`.

**FR-03. SPRT.** `voiceguard.fusion.sprt.SPRT(alpha, beta, t_max_s, prior_llr=0.0)`:

- `update(window: float, llr: float) -> WindowScore` накапливает `Λ = prior_llr + Σ llr_t`;
- `A = ln((1 − β)/α)`, `B = ln(β/(1 − α))`;
- `Λ ≥ A` → `suspicious`; `Λ ≤ B` → `normal`; после `t_max_s` секунд речи без решения → `undecided`; иначе `pending`;
- после решения состояние замораживается, дальнейшие `update` возвращают тот же вердикт;
- `prior_llr` — вход для будущих сетевых признаков (D3); в MVP равен 0.

**FR-04. Симуляция звонков.** `python -m voiceguard.fusion simulate --split test --channel amrnb_12.2`: каждый тестовый клип рассматривается как звонок; сегменты подаются в SPRT по порядку. Клипы короче `t_max_s` допускается склеивать из нескольких клипов того же диктора и класса до 30 с (флаг `--concat`). Результаты — по звонку: вердикт, время до вердикта (секунды речи), итоговое Λ.

**FR-05. Эмпирические ошибки.** По результатам симуляции:

- `α̂` = доля `suspicious` среди живых звонков; `β̂` = доля `normal` среди синтетических; доля `undecided` по классам;
- верхняя односторонняя 95% граница Клоппера–Пирсона: `α_up = beta.ppf(0.95, k + 1, n − k)` (`scipy.stats.beta`), при k = 0 — «правило трёх» для справки;
- среднее и 90-й процентиль времени до вердикта по классам.

**FR-06. Подбор порогов.** `python -m voiceguard.fusion tune --target-alpha 0.001`: если `α_up` выше цели, порог A сдвигается вверх шагом 0,25 до выполнения (не более 40 шагов); итоговые A и B и полученные α̂, α_up, β̂, E[T] сохраняются. Подбор делается на части `calib`, итоговая проверка — на `test` (без повторной подстройки).

**FR-07. Паспорт детектора.** `data/models/passport.json`:

| Поле | Содержание |
|---|---|
| `version`, `code_hash`, `created_at` | Идентификация |
| `detectors` | Состав (D1, D2-вариант, класс кадров), пути к моделям и эталонам |
| `channel` | Канал проверки |
| `thresholds` | A, B, t_max_s |
| `alpha_hat`, `alpha_up95`, `beta_hat`, `undecided_rate` | Измеренные ошибки на `test` |
| `time_to_verdict` | Среднее и p90 по классам |
| `n_calls` | Число живых и синтетических звонков |
| `generators` | Генераторы в тесте, отдельная строка для невиданных |
| `limitations` | Текстовый список ограничений |

`python -m voiceguard.fusion passport` печатает паспорт в читаемом виде.

## 4. Критерии приёмки

- **AC-01.** Тест: SPRT на последовательности `llr = +1` выдаёт `suspicious` на шаге ⌈A⌉; на `llr = −1` — `normal` на шаге ⌈|B|⌉; на `llr = 0` — `undecided` после `t_max_s`.
- **AC-02.** Тест: на синтетических данных (llr из N(+μ, 1) и N(−μ, 1), независимые окна) эмпирические α и β при 10 000 звонков не превышают заданных более чем в 1,5 раза.
- **AC-03.** Тест: `α_up` при k = 0, n = 3000 ≈ 0,001 (правило трёх).
- **AC-04.** Команды `simulate`, `tune`, `passport` отрабатывают на результатах ЧТЗ-07; паспорт содержит все поля.
- **AC-05.** Отчёт о сдаче: таблица α̂, α_up, β̂, E[T] для `use_d2 = true` и `use_d2 = false`.

## 5. Указания агенту

- Соседние окна одного диктора коррелированы, поэтому теоретические α и β SPRT не гарантируются. Оценки, приводимые в паспорте, — только эмпирические.
